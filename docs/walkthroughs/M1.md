# M1 walkthrough: searchable index (steps 1.3 and 1.4 done, 1.5 and 1.6 to do)

## What was built

Step 1.3, loader (`src/rag/ingest.py`). Reads `data/corpus_manifest.csv` and turns each of the 50 rows into one record in `data/processed/documents.jsonl`. The manifest is the source of metadata. The loader never writes to it.

Step 1.4, chunking (`src/rag/chunking.py`). Three variants, all written to `data/processed/chunks_v1.jsonl`, `chunks_v2.jsonl` and `chunks_v3.jsonl`.

## Results (real runs)

| Variant | Chunks | Avg tokens | Max tokens |
|---|---|---|---|
| V1 fixed | 52 | 238 | 405 |
| V2 by heading | 230 | 55 | 434 |
| V3 one per document | 52 | 240 | 448 |

Tests: 18 passed (`tests/test_chunking.py` 13, `tests/test_ingest.py` 5).

## Why V3 has 52 chunks, not 50

V3 is one chunk per document. The POL-04 glossary table is too long for the 450-token cap, so it splits into 2 chunks. 50 + 2 = 52.

## Key logic

Manifest first. Metadata (owner, certification, doc type) comes from the manifest, so the YAML header is not needed for it.

PDF headings come from font size. Bold at 16pt or more is `#`, bold at 12pt or more is `##`.

Tables are read cell by cell. Each row becomes `ID: KPI-001 | Owner: ... | Status: ...`, so a value always stays next to its label.

Token estimate is characters divided by 4. The cap is measured with the header included, because the header is part of what the embedding model sees.

Cuts prefer line breaks, then spaces. A table row is never split in half.

## Decision: POL-04 table format

Three options were measured on the glossary table.

| Option | Format | Tokens | Chunks |
|---|---|---|---|
| Scrambled text (pypdf, earlier) | cells run together | 664 | 2 |
| A. Labels on every row (kept) | `ID: ... \| Owner: ...` per row | 816 | 3 |
| B. Header once | column names once, then values | 618 | 2 |
| C. Labels on Owner and Status only | partial labels | 681 | 2 |

We keep A. Owner and status stay unambiguous, which matters more than the extra tokens. The cost is one more chunk under V1.

## Interview questions (answered)

1. Why does the loader read the owner from the manifest, not the YAML? The manifest is the single source of truth and holds the owner, certification and doc type. YAML is mostly body text and headings are removed.
2. Why does `load_pdf` use font sizes to find headings? Size shows the structure of the page without needing the wording, so section and subsection context is kept.
3. Why does V2 average 55 tokens and V3 240? V2 cuts at each heading, so each chunk is one section. V3 keeps the whole document together.
